# WF-04 流程记录与兼容

## objective

提供显式、版本化流程与可核验的节点验收归属，保持旧台账可读。

## context

- [行为规格](../../design/skill-workflow-spec.md)：正本合同，验收 AC08、AC09、AC10。
- [总体计划](../skill-workflow-plan.md)：阶段、依赖、隔离和交付范围。
- [模块分析](../analysis/skill-workflow.md)：集成关系。
- [上游研究](../../research/upstream-skill-map.md) 与 [Orca 研究](../../research/orca-mechanisms.md)：取证版本和原文来源。

## path

两个 scripts/ledger.py 及必要的新流程模块；references/ledger.md、chain-run.md；tests/test_ledger.py；schema/fixture。

以上均相对仓库根；涉及两语言包的文档同时修改，脚本保持字节相同。实施前核对实际路径；范围扩大回到 spec 审阅。

## delivery

先确定数据 schema 和升级/降级行为；封闭字段兼容；未知版本拒绝推断；流程与 tracker 权威分离。

交付机器可验证的 schema/validator、旧版台账 fixtures、有效与无效流程样本，以及待用户、受阻、失效、跨 Run 导入的输入/预期输出样例。WF-05 通过这些公开样例消费合同，不自行发明状态或字段。

## verification

使用真实临时文件验证追加、读取、归属、同 ID 冲突、旧 schema、失效传播、跨 Run 导入、产物版本变化；不得自动改写旧台账。

由独立 verify 对照 spec 审阅，记录命令/输入、实际结果和证据；未执行填未验证。不得仅根据代码形状或关键字宣布行为通过。

## completion

产物可审阅，适用验收条目有证据，blocking findings 已修复，依赖连接无 stub，状态才可改 done。PR 和合并以用户授权为准。
